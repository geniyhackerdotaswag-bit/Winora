# Winora: раздача и обновление

**Дата:** 2026-08-23
**Состояние:** согласовано с владельцем, готово к плану
**Предшествует:** переносимая сборка одним `.exe` (сделана 2026-08-23, 88 МБ)

## 1. Задача

Winora должна доходить до людей, которые не имеют отношения к разработке, и
обновляться у них без просьб и объяснений. Сегодня она существует одной
MSIX-установкой на машине владельца; получить её больше некому и неоткуда.

Считаем сделанным, когда:

- посторонний человек скачивает один файл и пользуется программой;
- при следующем запуске после выхода новой версии он видит об этом полоску;
- одно нажатие приводит его на новую версию, и он не покидает приложение;
- владелец выпускает версию одной командой и не держит токенов на своей машине.

## 2. Решения владельца

Приняты 2026-08-23, каждое закрывает развилку:

| Развилка | Решение |
|---|---|
| Откуда скачивать | Открыть `geniyhackerdotaswag-bit/Winora`, релизы в нём |
| Что делает кнопка | Скачивает и перезапускается |
| MSIX-сборка | Владелец сам переходит на переносимую |
| Куда попадает файл | Предлагает установиться при первом запуске |
| Как рождается релиз | GitHub Actions по тегу |

История репозитория проверена на секреты перед решением открыть его: 35
коммитов, ни токенов, ни ключей, ни `.env`. Единственное совпадение по слову
«token» — `DesignTokens.xaml`.

## 3. Версия

Источник один: тег. `v0.4.0` → workflow передаёт `-p:Version=0.4.0` → это
попадает в `AssemblyInformationalVersion`, который `AppEnvironment.Version` уже
читает. `Package.appxmanifest` перестаёт быть источником и остаётся только для
MSIX-сборки, которую больше никто не ставит.

`AssemblyInformationalVersion` может нести суффикс (`0.4.0+a1b2c3d`), поэтому
разбор обрезает всё от `+` и от `-` и только потом читает `Version.Parse`.

Сравнение — разбором, а не строками. У `BypassReleaseCheck` сравниваются строки,
и для чужих тегов это верно: их формат нам не принадлежит. Для своих даёт ложное
«доступно обновление» всякий раз, когда владелец сидит на сборке новее
опубликованной, — то есть постоянно. Обновление предлагается **только** когда
`latest > current`, обе разобрались и обе не пусты.

## 4. Составные части

Всё новое — в `src/Winora.System/Updates/`. Соседство с
`Winora.System/Windows/BypassReleaseInstaller.cs` намеренно: тот ведёт ровно
такой же разговор с GitHub, и его решения (заголовок `User-Agent`, «нечитаемая
лента — это не обновление», согласие до установки) здесь повторяются, а не
изобретаются заново.

Ни одна из частей не знает про WinUI.

### `AppReleaseFeed`

Спрашивает `https://api.github.com/repos/geniyhackerdotaswag-bit/Winora/releases/latest`.
Возвращает `AppRelease(Version, Tag, Notes, DownloadUrl, ChecksumUrl, SizeBytes,
PublishedAtUtc)` либо `null`.

`null` означает «не знаю» и никогда не превращается в «обновление есть». Нет
сети, лимит GitHub, изменившийся формат ответа — всё это `null`.

Нужный файл в релизе ищется по имени `Winora.exe`, контрольная сумма — по
`Winora.exe.sha256`. Отсутствие любого из двух — тоже `null`: половина релиза
хуже, чем его отсутствие.

### `AppInstallLocation`

Отвечает на три вопроса: где лежит текущий процесс, где положено лежать
установленной программе (`%LOCALAPPDATA%\Programs\Winora\Winora.exe`) и одно ли
это место.

Имя файла — часть ответа. Сборка выдаёт `Winora.App.exe`, релиз называется
`Winora.exe`; совпадать должны и папка, и имя. Побочная польза: сборка из-под
отладчика никогда не считается установленной, и разработка не пытается обновить
сама себя.

Отдельно от установщика потому, что этот же ответ нужен полоске обновления: она
показывает разные кнопки для установленной копии и для запущенной из «Загрузок».

### `AppInstaller`

Первый запуск не по адресу. Копирует текущий файл в папку программ, создаёт
ярлык в меню Пуск через COM-интерфейс `IShellLink`, запускает копию, закрывается.

Прав администратора не требует: обе папки принадлежат пользователю.

### `AppUpdater`

Скачивает, проверяет, подменяет, перезапускает. Разбор — в разделах 6 и 7.

### `UpdateViewModel` и полоска

Один `InfoBar` в оболочке (`MainWindow.xaml`, строка 0 рядом с заголовком).
Скрыт, пока показывать нечего.

## 5. Первый запуск

```
запуск  →  AppInstallLocation: я на месте?
              да  → обычная работа
              нет → окно: «Установить Winora в <точный путь>?»
                       «Установить» → копия, ярлык, запуск копии, выход
                       «Не сейчас»  → обычная работа отсюда же
```

Отказ не тупик. Программа работает из «Загрузок» как есть; меняется только одно —
полоска обновления предлагает открыть страницу релиза вместо «Обновить», потому
что подменять файл, о котором мы не договаривались, нельзя.

«Не сейчас» не запоминается: спросим при следующем запуске. Человек, скачавший
программу «посмотреть», второй раз запускает её уже намеренно, и это лучший
момент спросить снова. Если это окажется навязчивым — добавим «больше не
спрашивать», но не раньше, чем это подтвердится.

## 6. Обновление

Проверка — один запрос в фоне при старте, плюс кнопка «Проверить» в Настройках.
Ничего не блокирует и ни о чём не сообщает, когда сказать нечего.

Нашлось новое — полоска: номер версии, заметки к релизу, «Обновить».

Подмена опирается на то, что Windows разрешает **переименовать** запущенный
`.exe`, хотя удалить или перезаписать его не даёт:

```
1. скачать рядом с целью        →  Winora.exe.new
2. проверить (раздел 7)         →  не прошло: удалить .new, сказать, ничего не менять
3. Winora.exe  → Winora.exe.old
4. Winora.exe.new → Winora.exe  →  не удалось: вернуть .old на место, сказать
5. запустить Winora.exe, выйти
6. при следующем старте удалить *.old
```

Отдельная программа-обновлятор не нужна. Порядок выбран так, что до шага 3
ничего не разрушено, а шаг 4 обратим: `.old` всё ещё рабочая программа.

Шаг 6 терпит неудачу молча: занятый `.old` удалится в следующий раз.

## 7. Проверка скачанного

Три проверки до подмены, все обязательные:

1. **Размер** совпадает с тем, что назвал GitHub в описании релиза.
2. **SHA-256** совпадает с содержимым `Winora.exe.sha256` из того же релиза.
3. **Файл начинается с `MZ`** — это подпись исполняемого файла Windows.

Третья ловит случай, когда вместо программы пришла HTML-страница ошибки или
страница входа прокси, — самый частый вид «скачалось, но не то». Первые две
ловят обрыв связи и запись на переполненный диск.

Доверие тут даёт HTTPS до GitHub, а не сумма: сумма опубликована там же, откуда
файл. Она защищает от испорченной загрузки, а не от подделанного релиза, и
описывать её как защиту от второго было бы неправдой.

## 8. Отказы

| Что случилось | Что видит человек |
|---|---|
| Нет сети при проверке | Ничего. Полоски нет |
| Лимит GitHub | Ничего |
| Загрузка оборвалась | «Не удалось скачать. Программа не изменена» |
| Проверка не прошла | «Файл скачался повреждённым. Программа не изменена» |
| Переименование не удалось | «Не удалось обновить, всё осталось как было» + ссылка на страницу релиза |
| Программа запущена не из папки программ | Полоска говорит «скачайте новую версию», кнопка открывает страницу |
| Диск полон | Ловится на шаге 2, дальше как «повреждённый» |

Общее правило: любая неудача оставляет работающую программу и говорит об этом
словами, а не молчанием.

## 9. MSIX

Сборка остаётся собираемой, весь этот слой в ней выключен по
`IDeploymentState.IsPackaged`. Подменить файл внутри `WindowsApps` невозможно, и
полоска, обещающая то, чего не будет, хуже отсутствующей.

Это защита, а не возможность: владелец переходит на переносимую сборку, и
MSIX-путём больше никто не пользуется.

## 10. Выпуск версии

`.github/workflows/release.yml`, запуск по тегу `v*`:

```
windows-latest
  dotnet publish src/Winora.App/Winora.App.csproj -c Release
      -p:WinoraPortable=true -p:Platform=x64 -p:Version=<тег без v>
      -o publish
  переименовать publish/Winora.App.exe → Winora.exe   (имя, под которым живёт релиз)
  посчитать SHA-256 → Winora.exe.sha256
  создать релиз с тегом, приложить оба файла
```

Токен владельца не участвует: `GITHUB_TOKEN` выдаётся GitHub на время запуска и
исчезает после. Сборка не зависит от того, что лежит у владельца в рабочей папке,
и выложить сборку с незакоммиченными правками нельзя по устройству.

Перед первым тегом: сделать репозиторий публичным.

## 11. Тесты

Скачивание, файловая система и `IShellLink` — за интерфейсами; в тестах подделки.

- Сравнение версий: новее, старее, равные, мусор в теге, суффикс `+sha`, пустое.
- «Не знаю» не превращается в «доступно обновление» — ни при `null`, ни при
  пустом теге, ни при отсутствующем файле в релизе.
- Релиз без `Winora.exe.sha256` отвергается целиком.
- Выбор пути: запущено из «Загрузок» / из папки программ.
- Порядок подмены: до переименования цель не тронута.
- Возврат при неудаче на шаге 4: `.old` возвращается на место.
- Каждая из трёх проверок раздела 7 отвергает свой случай по отдельности.
- `*.old` удаляется при старте, занятый — не роняет запуск.

## 12. Чего сознательно не делаем

- **Не подписываем.** Сертификат стоит денег, которых сейчас нет. Следствие
  описано в разделе 13.
- **Не обновляем молча.** Winora меняет систему; в коде уже записано это правило
  для загрузки zapret, и здесь оно то же.
- **Не делаем откат на предыдущую версию.** Старые версии остаются на странице
  релизов; отдельный путь отката — это второй механизм подмены ради редкого
  случая.
- **Не делаем отдельный установщик.** Владелец просил один файл.
- **Не делаем каналы (бета/стабильная).** Пользователей пока считаные единицы.
- **Не запоминаем «пропустить эту версию».** Полоска закрывается на сеанс; если
  окажется навязчивой, добавим.

## 13. Что останется нерешённым

**Предупреждение Windows.** Файл не подписан, поэтому при первом запуске у
каждого появится «Windows защитила ваш компьютер». Обойти нельзя ничем, кроме
сертификата. Значит — описать в `README`: «Подробнее» → «Выполнить в любом
случае». Репутация копится по числу скачиваний и со временем предупреждение
уходит само.

**Размер.** 88 МБ на скачивание и около 220 МБ распаковки во временную папку при
первом запуске. Это цена самодостаточной сборки: у друга нет ни .NET, ни Windows
App SDK. Первый запуск заметно медленнее последующих.

**Антивирусы.** Неподписанная программа, которая скачивает и подменяет себя,
выглядит для эвристик подозрительно. Предсказать заранее нельзя; если всплывёт,
лечится тем же сертификатом.
