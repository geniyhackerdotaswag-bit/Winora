# Winora: переделка макета — план работ

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Привести все экраны к одному макету, убрать диагностический текст со строк настроек и превратить экран обхода из меню в перебор.

**Architecture:** Заголовок страницы становится одним элементом `PageHeader` вместо девятнадцати копий разметки. Настройки переезжают с карточек на строки — макет, который уже используется на «Панели задач». Причина недоступности уходит из тела строки в подсказку замка, а над списком встаёт одна фраза с кнопкой. Экран обхода получает состояние наверху и память о попытках; имена стратегий не меняются ни на символ.

**Tech Stack:** WinUI 3 / Windows App SDK 2.0.4, .NET 10, CommunityToolkit.Mvvm, xUnit.

**Согласованный макет:** артефакт «Winora — предложение по макету», вторая редакция.

## Global Constraints

- Модели представления не обращаются к `Winora.System` и `Winora.Infrastructure` — этого требует `ViewModelBoundaryTests`, и он сканирует **исходный текст**, включая комментарии: назвать этот слой даже в замечании — уронить тест.
- `[ObservableProperty]` объявляется только как `public partial string X { get; set; }` — MVVMTK0045.
- Каждый ключ ресурса из `.cs` и `.xaml` обязан существовать в `Resources.resw` с непустым значением — `ResourceKeyTests`.
- **Имена стратегий обхода не меняются.** `BypassStrategyCatalog` объясняет почему: имя файла — идентификатор, по которому человек сверяется с советом на форуме, а не подпись. Переводить, сокращать и переименовывать их нельзя.
- Тестовый проект `Winora.App.Tests` не ссылается на сборку App, а **компилирует её исходники по одному**. Новая модель представления, которую надо покрыть тестами, добавляется в `<Compile Include>` — и только если она не тянет за собой типы WinUI.
- Сборка: `dotnet build src/Winora.App/Winora.App.csproj -c Release -p:Platform=x64`. Тесты: `dotnet test -c Release`.
- Проверка на экране: опубликовать, поставить поверх `%LOCALAPPDATA%\Programs\Winora\Winora.exe`, снять `CopyFromScreen` после `SetWindowPos` в topmost. Файл **не переименовывать** — WinUI ищет `resources.pri` по имени модуля.
- Окно регистрации показывать только скриптом, который закрывает его сразу после кадра и держит копию `profile.json`: 26 августа открытый мастер перезаписал профиль владельца.

**Что делает.** Полоса с градиентом, названием в 40 пунктов и водяным знаком на 96 пунктов заменяется на строку: название в 20 пунктов, рядом — одна фраза о том, что этот экран делает, снизу тонкая линия. Высота с ~190 px до ~56 px на каждом экране.

Водяной знак уходит совсем: он повторяет значок, который уже подсвечен в панели слева, и занимает правую половину полосы ради этого повтора.

- [ ] **Шаг 1: Элемент**

`PageHeader.xaml` — `UserControl` с двумя свойствами зависимости, `Title` и `Subtitle`, и нижней границей `WinoraCardStroke`. `Subtitle` пустой — строка не рисуется, а не оставляет дыру.

- [ ] **Шаг 2: Подписи**

По одной строке на экран, ключ `Page_Sub_<Route>`. Пишутся от лица того, что экран делает, а не чем он является: «Как Windows двигает окна, меню и списки», а не «Настройки анимаций».

- [ ] **Шаг 3: Замена**

В каждом из 19 файлов блок `<Grid Background="{ThemeResource WinoraHeader…}">…</Grid>` заменяется на `<ctl:PageHeader Title="…" Subtitle="…" />`. Стили `WinoraPageTitle`, `WinoraRule*` и кисти `WinoraHeader*` после этого не используются нигде — удалить, чтобы не остались как приманка.

## Task 3: Причина недоступности уходит со строки

**Files:**
- Modify: `src/Winora.App/Controls/SettingRow.xaml(.cs)`, `ThemesPage`, `Resources.resw`
- Modify: `src/Winora.App/Views/TaskbarPage.xaml(.cs)` — тот же приём

**Что делает.** `winora_capability_target_not_writable` — «Настройку видно, но записать её этой учётной записи нельзя» — это код причины из ядра, выведенный дословно туда, где должно стоять описание настройки. Восемь раз подряд на одном экране.

- Строка говорит, что настройка делает.
- Справа — значок замка вместо переключателя.
- **Точная причина остаётся**, но в подсказке замка: она нужна тому, кто разбирается, и мешает всем остальным. Ни одна причина не выбрасывается и не подменяется общей фразой — их одиннадцать, и они означают разное.
- Над списком, один раз: `Нужны права администратора.` — **дословно та строка, что уже есть** (`Cleanup_NeedsAdministrator`), плюс кнопка перезапуска. Двух формулировок одного факта быть не должно.

**Порядок строк не меняется.** Раскладывать запертые настройки в отдельную группу рассматривалось и отвергнуто: экран выглядел бы по-разному в зависимости от того, как запущено приложение, и настройка, найденная вчера, сегодня лежала бы в другом месте.

Кнопка перезапуска показывается, только когда `IElevationRelauncher` действительно может это сделать; если у учётной записи нет прав администратора вовсе — причина другая (`elevation_unsupported_for_current_account`), и кнопки быть не должно.

- [ ] **Шаг 1: Тест на модель: список причин, при которых предлагается перезапуск**
- [ ] **Шаг 2: Полоса, замок, подсказка**
- [ ] **Шаг 3: Сборка, тесты, снимок, коммит**

## Task 5: Обход — состояние наверху и память о попытках

**Files:**
- Create: `src/Winora.Core/Bypass/BypassAttempt.cs` — запись о попытке
- Create: `src/Winora.Infrastructure/Bypass/BypassAttemptStore.cs` — хранение
- Modify: `src/Winora.App/ViewModels/BypassViewModel.cs`, `Views/BypassPage.xaml(.cs)`
- Test: `tests/Winora.Core.Tests`, `tests/Winora.Infrastructure.Tests`

**Что делает.** Двенадцать одинаковых плиток лежат так, будто из них выбирают со знанием дела. Какая заработает — не знает никто, включая автора zapret: это перебор. Экран должен вести перебор.

**Наверху — состояние**, крупно: работает обход или нет и на какой стратегии. Сейчас это спрятано в строку «Работает другая программа» над двумя серыми кнопками.

**Список — строки в порядке репозитория**, у каждой имя моноширинным (это идентификатор для сверки с форумом) и отметка: работает сейчас / не помогла, с датой / не пробовали.

**Отметку «не помогла» ставит человек.** Winora не может знать, открылся ли Discord. После запуска внизу появляется одна строка: «Заработало?» — «Да» / «Нет, следующая». «Нет» помечает стратегию и подставляет следующую по порядку.

Хранение: `%USERPROFILE%\Winora\State\bypass-attempts.json`, через существующий `AtomicJsonFile`. Запись — идентификатор стратегии, отметка времени, исход. Испорченный файл читается как «попыток не было»: это украшение перебора, а не состояние системы.

- [ ] **Шаг 1: Core — запись и правила (что считается «последней рабочей»)**
- [ ] **Шаг 2: Infrastructure — хранилище, тесты на испорченный и отсутствующий файл**
- [ ] **Шаг 3: Модель представления — состояние, список, ответ «заработало?»**
- [ ] **Шаг 4: Разметка, сборка, снимок, коммит**

## Task 6: Журнал изменений на человеческом языке

**Files:**
- Modify: `src/Winora.App/ViewModels/ChangesViewModel.cs`, `Views/ChangesPage.xaml`
- Modify: `Resources.resw`

**Что делает.** Экран, который доказывает, что программу можно отыграть назад, показывает `MicrosoftEdgeAutoLaunch_48EDF2D71EE0AC2F5D41DCF1908B2D8F: enabled → disabled`.

- Запись — предложение: «Microsoft Edge больше не запускается при входе».
- Под ним: дата словами и прежнее состояние — «было: запускался».
- Кнопка — **«Вернуть»**, не «Отменить»: «отменить» рядом с крестиком читается как «отменить то, что я сейчас делаю», а речь о возврате прежнего состояния.
- Слева значок раздела, откуда изменение.

Где предложения взять: для автозагрузки имя записи — это имя программы плюс мусор после подчёркивания, и разбор даёт «Microsoft Edge». Для настроек ключ уже сопоставлен человеческому названию — оно и сейчас показывается («Группировка на других экранах»), не хватает только глагола вокруг него.

**Чего не делать:** не выдумывать предложение там, где сопоставления нет. Неизвестная запись показывается как есть — сырое имя честнее выдуманной фразы.
